# 1. 项目定位

清商是一个面向宋词阅读与赏析的垂类 Agentic RAG 知识助手。通过意图识别、工具调用、Skill 路由，调用多个垂类领域能力（作品问答、格律分析、典故/化用识别、评论检索、结构化赏析），结合本地知识库、外部 API、规则引擎、LLM 推理，生成上下文问答与阅读增强结果，支持引用溯源、结果校验。

简历版本

```
清商：面向宋词阅读与赏析的垂类 Agentic RAG 知识助手。支持意图识别、Skill 路由、工具调用、引用溯源与结果校验，可完成作品问答、格律分析、典故/化用候选发现、评论检索和结构化赏析。
```

## 基本布局

清商 v0.1 采用“阅读器 + 助手”的双模式。
阅读器模式用于作品展示、注释、典故/化用候选、历代评论和结构化赏析生成。
助手模式用于用户划词/划句追问，系统根据问题进行意图识别与 Skill 路由，调用本地 RAG、搜韵 API、格律规则引擎和评论检索工具，汇总证据后生成带引用溯源与结果校验的回答。

阅读器在左侧，交互窗口在右侧。如果需要检索或展示相关内容，则把反馈的内容覆盖左侧阅读器的内容。

其中典故或注释可以考虑光标悬浮在指定文字上时浮现，也可固定在正文下面

以下是阅读器的界面基本要素（样例见附录）

# 2. 系统模块

## 系统架构分层与核心模块

清商 v0.1 采用分层架构，将前端阅读器、API 服务、Agent 编排、工具调用、知识库、上下文记忆、结果评测与缓存任务管理解耦。系统既支持固定流程的作品阅读增强，也支持右侧问答助手中的意图识别、Skill 路由与多工具调用。

### 1. Frontend / Reader UI Layer

负责词作展示、注释/典故高亮、右侧问答窗口和工具调用轨迹展示。

核心职责：

- 展示词牌、标题、作者、题序、正文等基础信息。
- 展示基础注释、典故/化用候选、历代评论和结构化赏析结果。
- 支持用户划词/划句追问。
- 展示 Agent 执行过程，包括识别意图、调用 Skill、使用工具、引用来源等。

### 2. API Layer

负责接收前端请求，并向前端提供统一接口。

核心职责：

- 作品查询接口。
- 上下文问答接口。
- 格律分析接口。
- 典故/化用候选发现接口。
- 结构化赏析接口。
- Agent 执行记录查询接口。

### 3. Agent Orchestration Layer

负责问答助手模式下的意图识别、Skill 路由、工具选择、证据汇总与最终回答生成。

核心职责：

- Intent Router：识别用户意图，如作品问答、格律分析、典故候选、评论解释、结构化赏析等。
- Skill Router：根据意图选择对应领域 Skill。
- Tool Planner：确定需要调用的工具链。
- Tool Executor：执行本地 RAG、搜韵 API、格律规则引擎、评论检索等工具。
- Evidence Collector：汇总工具返回的证据。
- Answer Synthesizer：调用 LLM 生成最终回答。

### 4. Tool Layer

封装系统可调用的外部工具和内部工具。

核心职责：

- Souyun API Tools：封装词谱、典故、化用、古籍检索等接口。
- Local RAG Tool：检索本地宋词知识库、评论、词话和赏析资料。
- Prosody Rule Tool：执行句式、平仄、韵脚、换韵等规则分析。
- Commentary Search Tool：检索历代评论和相关评注。
- Citation Tool：整理引用来源和出处信息。

Tool Layer 是 Agent 调用外部知识和确定性规则的入口，避免 LLM 直接凭空判断。

### 5. Knowledge Layer

负责存储和检索系统内部知识资源。

核心职责：

- 存储宋词正文、作者、词牌、题序等结构化数据。
- 存储注释、典故、评论、词话、赏析资料等文本资源。
- 存储 RAG 所需的文档 chunk 与向量索引。
- 支持作品、作者、词牌、关键词、语义相似度等检索方式。

### 6. Context & Memory Layer

负责维护当前阅读上下文、多轮对话上下文和 Agent 执行记忆。

核心职责：

- Reading Context：记录当前作品、作者、词牌、选中文本、所在句段。
- Conversation Memory：记录当前会话的多轮问答历史、上一轮意图和上一轮 Skill。
- Agent Run Memory：记录每次意图识别、Skill 路由、工具调用、证据汇总和最终回答。
- v0.1 只维护任务相关记忆，不做长期用户画像和复杂个性化推荐。

这一层主要支撑“左侧阅读器 + 右侧问答助手”的上下文追问能力。

### 7. Evaluation Layer

负责对 Agent 输出结果进行结构化校验、引用校验和规则一致性检查。

核心职责：

- 检查结构化赏析是否符合预设 schema。
- 检查典故/化用候选是否带有出处。
- 检查历代评论是否保留原文与来源。
- 检查格律分析结果是否与规则引擎输出一致。
- 对缺乏证据的判断进行降级或标注为“可能”。

Evaluation Layer 不追求替代人工判断，而是降低 LLM 幻觉和无依据断言。

### 8. Cache / Task Layer

负责缓存复用、异步任务执行和长任务状态管理。

核心职责：

- 缓存作品注评快照。
- 缓存搜韵 API 等外部接口结果。
- 缓存常用 RAG 检索结果。
- 管理异步任务状态，如 PENDING、RUNNING、SUCCESS、FAILED。
- 支持作品注评生成、索引重建、批量典故分析等长任务。

v0.1 中，实时问答和单次分析优先同步执行；作品注评生成、知识库索引构建等耗时任务进入异步队列。

## Tool Contract 设计原则

清商中的 Tool 不直接暴露第三方 API 细节，而是先定义系统内部统一的输入、输出、依赖和失败策略。

每个 Tool 至少包含：

- Tool Name：工具名称
- Belongs To Skill：所属领域 Skill
- Purpose：工具用途
- Input Schema：Agent 调用该工具时传入的结构化参数
- Output Schema：工具返回给 Agent 的统一结果格式
- Dependencies：依赖的数据源、外部 API 或本地规则库
- Failure Strategy：失败、无结果、超时或低置信度时的处理方式

# 4. Agentic workflow

用户选择阅读器的作品 -> 查询缓存 -> 查询数据库 -> 调用API生成注评 -> 返回结果

用户输入 -> 意图识别 -> 工具选择 -> 上下文拼接 -> 调用LLM -> 整理结果 -> 评测结果 - 返回前端

### A. Reader Flow：作品阅读增强流程

用户进入阅读流 / 选择作品
→ 查询作品基础信息
→ 查询 annotation_cache
→ 返回正文、题序、作者、词牌、已有注释与已有注评快照
→ 如果注评快照完整，直接展示
→ 如果注评快照缺失或版本过期，创建后台注评任务
→ 前端先展示正文与已有内容
→ 后台调用典故/化用候选、评论检索、本地 RAG、结构化赏析工具
→ 生成 annotation_snapshot
→ 写入缓存
→ 前端轮询任务状态或通过提示刷新内容

### B. Assistant Flow：用户追问流程

用户输入问题 / 划词划句追问
→ 构造 Reading Context，包括当前作品、选中文本、前后文、作者、词牌
→ Intent Router 判断任务类型
→ Skill Router 选择领域 Skill
→ Tool Planner 选择工具链
→ Tool Executor 调用本地 RAG / 搜韵 API / 格律规则引擎 / 评论检索工具
→ Evidence Collector 汇总证据
→ LLM Synthesizer 生成回答
→ Quality Checker 检查引用、结构、越界解释
→ 返回答案 + 引用来源 + 工具调用轨迹

## 同步/异步任务划分

实时问答同步执行。
比如划词追问、单句典故查询、单首词格律分析。

作品注评生成异步执行。
因为一首词的注释、典故、化用、评论检索、AI 赏析可能慢，而且适合缓存。

## 数据库表草案

分为文本数据和向量数据。文本数据是静态展示的内容，比如词作、作者信息。向量数据库保存 RAG 所需的内容，比如词话、集评、今人著作等等

## 数据模型草案

清商 v0.1 的数据模型分为五类：作品基础数据、注评与引用数据、RAG 知识库数据、会话与 Agent 运行数据、评测与缓存数据。当前阶段先定义核心实体，具体字段、索引和外键在实现过程中根据接口契约逐步细化。

### 1. 作品基础数据

#### ci_poems
存储词作正文、词牌、题序、作者、朝代、来源等基础信息。

#### authors
存储作者姓名、朝代、生卒年、简介等基础信息。

### 2. 注评与引用数据

#### annotation_items
存储注释、典故、化用、评论等结构化条目。  
每条记录对应一个具体落点，如某字、某句、某个意象或某处典故候选。

#### annotation_snapshots
存储某首词的整页注评快照，包括基础注释、典故/化用候选、历代评论、结构化赏析等聚合结果。  
用于 Reader Flow 中的缓存命中和渐进加载。

#### source_refs
存储引用来源，如书名、卷次、作者、原文片段、URL、API 来源等。  
用于引用溯源、结果校验和前端展示。

### 3. RAG 知识库数据

#### rag_documents
存储进入 RAG 的文档元信息，如词话、评注、诗话、研究文章节选等。

#### rag_chunks
存储切分后的文本块、embedding、来源引用、chunk 顺序和元信息。  
用于向量检索、相似文本召回和引用溯源。

### 4. 会话与 Agent 运行数据

#### chat_sessions
记录一次阅读/问答会话，包括当前作品、阅读模式、会话状态和创建时间。

#### chat_messages
记录用户输入、助手回答、选中文本、消息类型和所属会话。  
用于多轮上下文追问。

#### agent_runs
记录每次 Agent 执行过程，包括用户输入、阅读上下文、识别意图、选择的 Skill、最终输出和状态。

#### tool_calls
记录每次工具调用，包括 tool_name、request、response、latency、status、error_message 等。  
用于工具调用轨迹展示、调试和失败分析。

### 5. 评测、缓存与任务数据

#### eval_results
记录输出质量检查结果，包括结构校验、引用校验、规则一致性检查、幻觉风险标记等。

#### task_runs
记录异步任务状态，如作品注评生成、索引重建、批量典故分析等。

#### api_cache
缓存外部 API 调用结果，如搜韵典故查询、词谱查询、化用分析结果等。

#### reading_streams
记录阅读流配置，如全集阅读、同词牌阅读、相似词阅读等。

v0.1 中可先实现全集阅读和基础相似词推荐；对比阅读、主题阅读流等作为后续扩展。


## API 草案

使用搜韵提供的 API 完成一些功能，比如典故、格律
使用萌典或台湾教育部国语字典 API 查询词汇
使用必应/Google API 在线查询多种信息（除了典故、格律、词汇，还有可能的诗句化用、今人评论、词作背景信息等等）

## AI 赏析输出协议 v0.1

清商不直接生成连续散文式赏析，而是要求 LLM 输出结构化结果。该协议用于约束 AI 输出，使赏析内容可以被前端分区渲染、被 Evaluation Layer 校验，并与引用来源、格律规则和工具调用结果关联。

### 1. 输出结构

AI 赏析结果包含以下视图：

- lexical_view：炼字、句眼与关键表达
- imagery_view：意象、空间、时间与情感网络
- allusion_view：典故/化用候选
- prosody_view：词牌格律、韵脚、平仄与声情
- comment_view：历代评论与评注摘录
- synthesis_view：基于前述视图的整体观察

### 2. 判断单元

除 synthesis_view 外，每个视图中的判断都应尽量包含以下字段：

- anchor_text：具体落点，如某字、某句、某个意象、某处韵脚
- claim：判断内容
- evidence：支持该判断的证据
- source：证据来源，如本地知识库、搜韵 API、历代评论、规则引擎
- confidence：置信度，取 high / medium / low
- note：必要时说明“不作确定性判断”或“仅为候选”

### 3. 质量约束

- 每个视图输出结构化数据，不输出连续文学评论散文。
- 每个判断必须有具体落点，避免“意境优美”“情景交融”等无锚点评价。
- 典故、化用、意象传统只做候选发现和来源呈现，不强行解释其功能。
- 历代评论应保留原文和出处，不由 LLM 任意改写。
- 格律、平仄、韵脚等判断优先来自规则引擎；LLM 只负责解释规则结果与作品内容之间的关系。
- synthesis_view 放在最后，只基于前面各视图的证据生成整体观察，不允许脱离证据空泛抒情。

### 4. 版本说明

该协议为 v0.1 版本，优先服务于作品阅读增强和结构化赏析。后续可根据实际效果调整视图数量、字段名称和校验规则，但应保持“结构化输出、具体落点、引用溯源、结果校验”的核心原则。

踏莎行
晏殊
细草愁烟，幽花怯露，凭栏总是销魂处。日高深院静无人，时时海燕双飞去。
带缓罗衣，香残蕙炷，天长不禁迢迢路。垂杨只解惹春风，何曾系得行人住！

晏殊的词一般都写得凄婉而且温润，不为激言烈响的劲切之辞，而却极其富于深微幽隐的感发之作用，这首《踏莎行》词，便是颇能表现出此种特色的一首好词。
开端“细草愁烟，幽花怯露”​，表面上看来只是景物的叙写：小草上的烟霭迷蒙，花蕊上的露珠泫照，所写都是外在的景象，而内含的却是极锐敏的感受。他所用的“愁”字和“怯”字，表现了晏殊极细腻的情思，且与细密的对偶形式完美地结合为一体。你看，春天里，那细草在烟霭之中仿佛是一种忧愁的神态，那幽花在露水之中仿佛有一种战惊的感觉。用“愁”来表达草在烟霭中的感受，用“怯”来描写花在晨露中的感受，表面上说的是花和草的心情，实际上是通过草与花的人格化，来表明人的心情，亦物亦人，物即是人。晏殊另一首《蝶恋花》之“槛菊愁烟兰泣露”句，可以与此相参看，境界相同，只是一个是秋景，一个是春景，但同样是在细小的形象中，表现了晏殊观察之纤细、幽微。敏锐和善感的诗人特质，投注了他细腻幽深的情思。
下面一个七字长句“凭栏总是销魂处”​，是前两个四字短句的总结，是感情上的一个总的叙述。这个结句告诉你，​“细草愁烟，幽花怯露”​，是词人靠在栏干上所见到的景物。凭栏远眺是常人的习惯，但人人都凭栏，人人都看风雨，人人都看江山，人人都看草，人人都看花，却唯有晏殊看到了细草在那春天的烟霭中有忧愁的意味，小花在晨露中有寒怯的感觉，并且竟能使他感到“销魂”​。你说“销魂”​，不是悲哀愁苦才销魂吗？可是晏殊却只因草上的丝丝烟霭的迷蒙，花上的点点露珠的泫照，就能使他“销魂”​，这才更见出词人之情意的幽微深婉。后面紧连两个七字句把上片总结起来：​“日高深院静无人，时时海燕双飞去”​。前面由写景转而写人，这两句则是以环境的衬托，进一步写人。​“静无人”是别无他人，唯有一个凭栏销魂的我在。​“日高深院静无人”的环境，衬托着人的寂寥。​“时时海燕双飞去”​，则是以“海燕双飞”反衬人的孤独，海燕是双双飞去了，给孤独的人却留下了一缕绵绵无尽的情思，在“日高深院”里萦回盘旋，渲染出一种孤寂之中的深沉的怅惘。
下片“带缓罗衣，香残蕙炷”​，由上片的室外转向室内，仍在写人。​《古诗十九首》曾云“相去日已远，衣带日已缓”​，写因怀念远去的人而消瘦、憔悴，这里的“带缓罗衣”​，以衣服宽大写人的消瘦，也暗示着离别。​“香残蕙炷”​，​“蕙”是蕙香，一种以蕙草为香料制成的熏香，古代女子室内常用。​“残”是一段段烧残。​“炷”是香炷，即我们常说的“一炷香”的“炷”​。​“香残蕙炷”是写室内点的蕙香，一段段烧成残灰。这又暗示着室内之人心绪的黯淡。秦观《减字木兰花》上片云：​“天涯旧恨，独自凄凉人不问。欲见回肠，断尽金炉小篆香。​”以香炉里烧成一段一段的篆字形的熏香的残灰，比拟自己内心千回百转的愁肠已然断尽，比拟自己的情绪的冷落哀伤，可以为这里作注。但晏殊并没有像秦观以“篆香”比“回肠”这样清楚地表明自己内心之情，他只是客观地写出“带缓罗衣，香残蕙炷”​，不明显、不激动，很含蓄。一般人念起来，因为很容易读懂，所以会一带而过，不再去作深一步体会。但晏殊的词是非细心体会不能得其妙处的。一读而过，他有多少离别相思怀念的情意，因为没有直说，便会被你所忽略了，岂不是入宝山而空手归的憾事？​《古诗十九首》所说的离别相思，秦观《减字木兰花》所写的愁肠断尽，都说出了各自的原因，​《古诗十九首》里是因为离别的人“相去日已远”​，结果才“衣带日已缓”​；秦观是因为“天涯旧恨，独自凄凉人不问”​，结果才断尽了回肠。晏殊却没有说。那么，他那一份怅惘怀思的情意，就果真是指现实的人与人的离别、怀念、相思吗？晏殊唯其不直说出来，所以才不受个别情事的拘限，才会使你想到整个人生该有多少值得你相思怀念的美好的情事，该有多少美好的人、事、物值得你交托，投注你的感情！这二句给人无限深远的想象与联想。
我们再接着看下一句的“天长不禁迢迢路”​，这仍是一个长句，为上二句作结，与上片的前三句句式相同，两个对偶的双式紧接一个单句，严密而完整。​“不禁”是不能阻拦。​“天长”与“迢迢路”​，是上面天长，下边路远，二者结合得很好，天长路远，这是没有什么办法阻拦的。​“不禁”二字，所表现的是对已消逝的远去的一切无法挽回的哀伤。紧接在“带缓罗衣”的思念与“香残蕙炷”的销磨之后，更增加了对于已经失落的无可奈何之感。然后在结尾的两句写出“垂杨只能惹春风，何曾系得行人住！”以感叹的口吻出之，留下了无尽的情意。杨柳柔条随风摆动，婀娜多姿，在晏殊看来，这多情、缠绵的垂柳，不过是在那里牵惹春风罢了，千条万缕的杨柳柔条，虽然从早到晚不住地摆动，但它哪一根柔条能把那要走的人留住？哪一根柔条能把那消逝的美好的往事挽回？这里象征着对整个人生的无可奈何的深刻感受，其中寄托有极深远的一片怀思怅惘之情，是要仔细吟味，才能体会得出的。
可能会有人认为，晏殊这里无非是表现了一种伤春的情绪，欣赏起来，于现实并无怎样重大深远的意义。当然，我们这里欣赏晏殊的词，并非是要大家同去伤春落泪，而是在晏殊的伤春情绪中，实在是有一种对时光年华流逝的深切的慨叹和惋惜存在，而且更在极幽微的情思的叙写中，流露出了很深挚又很高远的一份追寻向往的心意。这种情意，虽然表面看来也许只不过是伤春怀人之情而已，但是隐然间却可以使读者的心灵感情感受到一种提升的作用，这种言外的引人感发联想的作用，正是词这种韵文所最值得注意的一种特质和成就。而五代时南唐的冯正中，和北宋初年的大晏、欧阳，则是在这方面表现得最富于高远深厚之含蕴的几位作者。
（叶嘉莹）
