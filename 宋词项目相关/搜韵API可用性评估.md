# 搜韵 API 可用性评估 —— 针对 songci-commentary 项目

## 概览
搜韵网 API 共 12 个模块，对于你的项目，**核心有用的是 3 个，完全能用**。

---

## 📊 模块评估清单

### ✅ **直接用（对你项目关键）**

#### 1. **词谱（ciTune）** — 关键模块 ⭐⭐⭐⭐⭐
```
GET /api/ciTune                      # 词谱总览（列出所有词牌）
GET /api/ciTune/{id}                # 查询特定词谱的详细信息
POST /api/ciTune/find               # 搜索词牌（按名称关键词）
POST /api/ciTune/pattern            # 按平仄句式模糊匹配词牌 ⭐
```

**评估：**
- ✅ 有词牌基础数据库（id 体系明确）
- ✅ 支持按名称模糊搜索（对"异文词牌"有帮助）
- ✅ **最关键的：`/api/ciTune/pattern` 接口！** 输入句子，返回匹配的词牌
- ⚠️ 需要验证：词谱详情里是否包含平仄数据（格律信息）

**建议：现在就试这个接口！**

---

#### 2. **诗文库（writing）** — 辅助模块 ⭐⭐⭐⭐
```
GET /api/writing/{writingId}/tones  # 为作品标注平仄 ⭐
POST /api/writing/find              # 按平仄句式查询律句
GET /api/writing/{writingId}        # 获取完整作品
```

**评估：**
- ✅ 诗文库有 100+ 万首古诗词
- ✅ **`/tones` 接口可以直接标注平仄！** 省去你自己做平仄标注的工作
- ✅ 可以用来对比你的词和已有词是否符合格律
- ℹ️ 这个可能会成为你的"地面真理"（ground truth）

**建议：绝对值得用！**

---

#### 3. **韵典（rhyme）** — 辅助但重要 ⭐⭐⭐
```
GET /api/rhyme/{rhymeBook}          # 获取韵书的韵目信息
GET /api/rhyme/{rhymeBook}/{rhyme}  # 获取某韵目的字表
POST /api/rhyme/find                # 查字在某韵书中的信息
```

**评估：**
- ✅ 支持平水韵、词林正韵等多套韵书
- ✅ 可以用来验证词的韵脚是否合规
- ℹ️ 用处是辅助性的，不是核心

---

### ⚠️ **可用但暂时不必用（v1 不需要）**

#### 4. **诗文库搜索/化用（writing/find, labelize）** ⭐⭐
```
POST /api/writing/find              # 组合搜索
POST /api/tool/reference            # 出处与化用分析（工具模块）
POST /api/tool/labelize             # 自动笺注
```
- ✅ 能用，但属于"增强功能"（v2+ 再考虑）
- 对应你原方案的"化用"和"意象"分析
- 暂时砍掉

---

#### 5. **工具（tool）** ⭐⭐
```
POST /api/tool/charsetConvert       # 简繁转换
POST /api/tool/labelize             # 自动笺注
POST /api/tool/reference            # 化用分析
POST /api/tool/texting              # 短信息查询
```
- ✅ 都能用，但对 v1 的"格律+声情"不关键
- 可能在后续增强时用到

---

### ❌ **对你项目不太相关**

- **古籍库**：查古籍文献，不是格律分析
- **曲谱**：这是戏曲曲谱，你要的是词谱，别混
- **人物**：词人信息，可选
- **类书**：古代百科全书，不必要
- **地理**：古代地理，可有可无
- **字典**：单字查询，可选
- **词汇、典故**：增强功能，v2+ 再说
- **年历**：时间转换，暂不需要

## 🎯 **对你项目的关键发现**

### 1. **词谱接口很强大**
```
POST /api/ciTune/pattern
Body: { "pattern": "对潇潇暮雨洒江天" }
```
这个接口是**黑科技**！你可以：
- 输入一个词句，它返回"有相同平仄结构的词牌"
- 省去了手工对比龙榆生词谱的工作
- **但要验证数据准确性**

### 2. **平仄标注有现成的**
```
GET /api/writing/{writingId}/tones
```
这意味着你不需要自己去实现平仄标注逻辑！搜韵已经做好了。
- 可以用来验证你的词的平仄标注是否正确
- 可以直接拿来展示给用户

### 3. **你省掉的工作**
如果用搜韵 API：
- ❌ 不需要自己清洗龙榆生 OCR 词谱
- ❌ 不需要自己实现中古音标注系统
- ❌ 不需要自己维护词牌数据库

**省下的时间可以用来：**
- ✅ 优化 LLM prompt（用《词学十讲》做声情分析）
- ✅ 做好前端展示
- ✅ 写更详细的博客和技术文档

## ⚠️ **需要验证的 3 个关键问题**

1. **词谱数据的完整性**
   - 是否覆盖全宋词的所有词牌？
   - 平仄格式的编码是什么？（平仄符号、数字、其他？）

2. **平仄标注的准确性**
   - `/writing/{id}/tones` 的标注准确吗？
   - 是否基于中古音还是现代汉语？

3. **API 的稳定性和限制**
   - 是否有频率限制？
   - 响应速度如何？
   - 数据是否经常更新？

## 💡 **技术栈决策**

基于上述评估，我建议：

| 选择 | 原因 |
|------|------|
| ✅ 用搜韵 API | 数据完整、节省开发时间、可专注于增值功能 |
| ✅ 做一个本地缓存层 | 减少 API 调用、提高响应速度 |
| ✅ 自己实现词牌识别逻辑 | 搜韵 API 只提供数据，识别算法还是要自己设计 |
| ⚠️ 关于平仄标注 | 先用搜韵的，后续如果有专门需求再自己实现 |
