# ADR-001: 使用搜韵 API 作为词谱与平仄数据源

## Status
Accepted（2026-05-07）

## Context
v1 需要词牌识别 + 平仄数据 + 韵脚位置等基础格律数据。
约束：
- 时间预算 10-14 天，词谱数据准备不能超过 1-2 天
- 个人作品集项目，不商用，没有数据合规压力
- 我自己不是词学专业，缺乏足够能力从原始书籍构建权威词谱库

## Decision
使用搜韵 API（https://open.cnkgraph.com）作为词谱、平仄、韵脚等基础数据的唯一来源。
具体使用接口：
- GET /api/ciTune/{id} —— 词谱详情
- POST /api/ciTune/pattern —— 平仄句式模糊匹配
- GET /api/writing/{id}/tones —— 平仄标注

## Consequences
好处：
- 省 2-3 天的词谱数据准备工作
- 数据权威性由搜韵保证，比我自己从龙榆生书 OCR 提取靠谱
- /pattern 接口提供了"反向查词牌"能力，本来要自己实现
- 释放出的时间可以投入到声情分析（项目真正的差异化点）

代价 / 风险：
- 依赖第三方 API，搜韵改接口或限流会影响项目
- 数据格式是黑盒，未来想做精细处理可能受限
- 必须做缓存层防止开发期反复请求

何时重新评估：
- 搜韵 API 出现稳定性问题
- v2 扩展到 API 未覆盖的维度（如音韵学拟音）

## Alternatives Considered
- A. 从龙榆生《唐宋词格律》OCR 提取词谱
  没选：需要 1 天 OCR 清洗 + 1 天 regex 调试，挤压声情分析时间。
  且我自己没能力验证 OCR 后数据的正确性。

- B. 手工维护一个常见词牌的小词谱库（150 词牌）
  没选：覆盖不全，遇到冷门词牌就回到原点。
  作为搜韵 API 失效时的 fallback 方案保留。

- C. 用本地 RAG 检索龙榆生词谱书
  没选：词谱是结构化数据，RAG 天然不适合（详见 ADR-0002）。
