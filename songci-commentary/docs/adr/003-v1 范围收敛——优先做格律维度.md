# ADR-003: v1 范围收敛——优先做格律维度

## Status
Accepted（2026-05-07）

## Context
最初的产品构想覆盖六个分析维度：格律、声情、典故、意象、章法（结构）、历代评论。

通过阅读龙榆生《词学十讲》第四讲（句度长短与表情关系）的，识别出一个现象：仅"格律"这一个维度，龙榆生在一段分析里就调用了至少六个子维度——曲调命名考据、句末平仄统计、句中律句模式、韵脚音质、长短句节奏、内容与格律的呼应。每个子维度要做扎实都需要 1-2 天。

约束：
- Sprint 时间预算 10-14 天
- 单人开发，无法并行
- 项目目标包含一篇有深度的技术博客 + 求职作品集叙事，要求至少有一个维度做到能讲透的深度
- 我自己不是词学专业，每个新维度都涉及额外的领域学习成本

按原计划六个维度同时做，每个维度只能做到 30-40% 的深度，最终交付物会是一个"看起来覆盖广但都浮在表面"的工具。这种交付物的产品价值、作品集价值、学习价值都低于"做透一个维度"的方案。

## Decision
v1 范围收敛到只做格律维度。

格律维度内部的 v1 范围：
- 词牌识别（依赖搜韵 API，见 ADR-0001）
- 平仄数据获取（依赖搜韵 API）
- 句度长短分析（基于龙榆生《词学十讲》第四讲）
- 韵位安排分析（基于龙榆生《词学十讲》第五讲）
- "和谐 vs 拗怒"综合判断（结构化知识 + LLM，见 ADR-0002）

## Consequences
好处：
- 产品定位清晰：与搜韵和古文岛等在线诗词网站形成差异——"基于龙榆生理论的格律深度分析工具"
- Sprint 可完成性大幅提高，10-14 天预算变得现实
- 作品集叙事强：面试时能围绕一个维度讲 15-30 分钟细节，比讲六个维度但每个三分钟更有说服力
- 学习深度有保证：能真正进入龙榆生的分析框架
- 技术架构能形成闭环：metrics.py（计算）+ knowledge.yaml（知识）+ voice_analyzer.py（LLM 综合）三层清晰

代价 / 风险：
- 短期看产品功能"显得少"，没有典故、意象等与内容直接相关的功能
- 词学爱好者的真实需求可能更偏向典故/翻译类辅助，纯格律分析的受众较窄

何时重新评估
- v1 完成并发布后，根据个人需求添加下一步分析
- 如果 v1 的格律分析在 sprint 中提前 3 天以上完成，可考虑把对偶（第六讲）作为 v1.1 加入
- 如果发现"只做格律"在产品体验上确实过于单薄，可降级深度、把典故分析作为 v1 的次要维度补回

## Alternatives Considered
- A. 保持原计划，六个维度都做但每个浅做
  没选：每个维度 30-40% 深度的产品没有差异化竞争力，也无法支撑深度博客和面试讲述。10-14 天预算不可能把六个维度都做扎实。

- B. 收敛到典故维度而非格律维度
  没选：典故分析的核心数据（出处、化用）搜韵 API 已经通过 /api/tool/reference 等接口提供，但不一定好用，自己再做一遍增值空间小，容易变成"搜韵前端包装"。格律分析则有龙榆生理论框架可以做出搜韵之外的深度。

- C. 收敛到声情分析（不含格律计算，纯文学解读）
  没选：。格律维度有"可计算指标 + 理论框架 + LLM 综合"的三层结构，工程上更有看点。纯文学解读考虑知识库的搭建，放在下一步进行。
