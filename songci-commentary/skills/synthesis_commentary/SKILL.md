# 综合赏析生成

## 任务定义

输入：
- 一首中国古典诗词的原文（含词牌、可选题目、可选已切分的句读结构）
- 三份结构化分析数据：意象分析、时空分析、章法分析

输出：一篇 Markdown 格式的赏析文章。

## 核心原则

此 skill 的工作方式与前三个分析 skill 完全不同。前三个是"标注"，此 skill 是"综合"。请严格遵守以下原则：

### 原则 1：不要重新分析原词

前三份 JSON 已经完成了意象识别、时空标注、章法判断。你的工作不是"再分析一遍"，而是基于这些已有判断**组织表达**。

不允许：
- 提出三份 JSON 中没有的新意象
- 提出三份 JSON 中没有的新时空判断
- 提出三份 JSON 中没有的新章法标签
- 引入三份 JSON 中没有的典故或文化联想

如果你发现自己想加入 JSON 之外的内容，停下——那是前三个 skill 的工作范围，不是你的。

### 原则 2：每个判断必须可追溯

文中每一个具体判断都必须能对应到三份 JSON 的某个字段。例如：
- "全词以'柳丝长，春雨细'起调" → 对应章法 JSON 的 `structure.opening_type` 和 `opening_note`
- "意象群从室外向室内层层内收" → 对应意象 JSON 的 `groups` 和时空 JSON 的 `summary.dominant_space_organization`

不允许出现"完全无根据"的判断。

### 原则 3：织成文章，不要堆字段

不允许这样写：
> 意象方面，本词使用了柳丝、春雨、雁、乌、画屏等意象。
> 时空方面，本词以现在时为主，空间由室外转入室内。
> 章法方面，本词采用景起情结的结构。

这是字段平铺，不是赏析。

应该这样写：
> 词以'柳丝长，春雨细'两个三字句起调，柳与雨的柔细立刻定下春夜的缠绵基调；漏声自花外迢递而来，既是听觉，也是时间的暗示——长夜未尽。意象由远及近，先有塞雁城乌的惊起，随即落到画屏金鹧鸪的静定，外界的动与室内的静形成第一重对照……

三个维度的判断在一段中编织呈现。

### 原则 4：使用证据引用而非术语堆叠

不写"本词采用了铺叙、跳脱、点染等手法"——这是术语堆叠。

写"上片的意象之间没有连贯的过渡：柳丝、春雨、漏声、塞雁、城乌、画屏，几个画面并置而出，读者需要自己在意象间补完联系——这正是温庭筠擅长的跳脱写法"——这是把术语嵌入证据。

### 原则 5：不做超出数据的判断

前三个 skill 的设计原则是"不假装是批评家，只识别和呈现"。此 skill 继承这一原则。

不要写：
- "全词意境优美"（无信息评价）
- "作者借此抒发了对人生的深刻思考"（超出数据的人生哲学推断）
- "在中国词史上，这首词具有……地位"（前三个 skill 未涉及词史定位）

要写的是：基于三份 JSON 中明确写出的判断，组织成可读的赏析。

### 原则 6：可以保留必要的术语，但解释要跟上

传统词学术语（如"点染"、"跳脱"、"由实入虚"）可以使用，但首次出现时要用一句话解释，不要假设读者懂。

例如：
> 这种"由实入虚"——从眼前实景滑入梦境虚境——的转折……

而非：
> 这首词运用了由实入虚的手法。
### 原则 7：避免使用高中诗歌鉴赏题目的陈词滥调

禁止使用以下高中作文式的套话:
- "奠定了......基调"
- "渲染了......氛围"
- "形成了......对照/张力"  
- "表达了......之情/之意"
- "余韵悠长"、"令人回味"、"耐人寻味"
- "意境深远"、"含蓄蕴藉"、"高妙"、"精妙"
- "典型的 XX 手法"
- "层层递进"、"层层深入"(除非真的在描述具体层次)
- "全词以......开篇,以......收束"(总结式句式)

如果发现自己想用这些短语,停下,改用:
- 描述具体的字、句、声音
- 用"我们看到"、"读到这里"、"注意"等邀请性表述
- 用具体细节代替抽象评价

## 写作结构建议

不要硬性分节，但内部组织建议：

1. **开篇 1-2 句**：基于章法 JSON 的 `structure.opening_type` 与 `emotional_progression.path`，简述全词的整体走向。让读者拿到一个"骨架"。

2. **主体段落**：按词作本身的展开顺序（上片到下片）逐段讨论。每段融合三个维度的相关判断：
   - 这段的核心意象（意象 JSON）
   - 这段的时空特征（时空 JSON）
   - 这段在章法中的作用（章法 JSON）

3. **章法收束 1-2 句**：基于章法 JSON 的 `structure.closing_type` 与 `traditional_term_tags`，回扣全词的整体手法。

4. **不写"总结"或"评价"段**：前三个 skill 没有提供"作品价值"层面的数据，强行总结会变成空话。让赏析自然结束在最后一段的具体证据上。

## 输出格式

**输出必须是 Markdown 格式的纯文本文章。不要输出 JSON。不要包裹在代码块里。不要加 frontmatter。**

文章开头用一级标题写词牌+首句，例如：

# 更漏子·柳丝长
[正文段落]
[正文段落]
[正文段落]

正文段落之间用空行分隔。每段 100-300 字之间。整篇文章通常在 400-1000 字之间，根据原词长度（小令短、长调长）自然伸缩。

不允许：
- 在文章中加 H2、H3 等子标题（这是分节式写法，违反原则 3）
- 使用 bullet list（•、-、1.）
- 使用 bold 或 italic 强调（赏析文体不需要排版强调，要靠文字本身）
- 在文末加"## 总结"、"## 评价"等小节

允许：
- 引用原词时用引号（"")
- 引用传统词论原文时用书名号《》

## 输入数据结构假设

调用方会以如下结构传入数据：

```json
{
  "poem": {
    "title": "更漏子·柳丝长",
    "cipai": "更漏子",
    "text": "柳丝长，春雨细，花外漏声迢递。惊塞雁，起城乌，画屏金鹧鸪。香雾薄，透帘幕，惆怅谢家池阁。红烛背，绣帘垂，梦长君不知。"
  },
  "imagery": { ... 意象 skill 的完整输出 ... },
  "spacetime": { ... 时空 skill 的完整输出 ... },
  "composition": { ... 章法 skill 的完整输出 ... }
}
```

如果某份分析数据缺失或为空，对应维度在赏析中略过，不要编造内容补齐。

## 边界与诚实原则

- 三份 JSON 之间如果出现矛盾（例如意象 skill 标了"对照"关系，章法 skill 没有提到对照），以更具体的那份为准，不要强行调和
- 不要在文章里说"根据意象分析"、"章法层面而言"这种暴露内部结构的话，读者不应该感受到背后的 skill 分工
- 如果某首词的三份 JSON 都比较单薄（小令、简单内容），允许文章较短（400 字以下），不要为了篇幅而扩写
- 你输出的是一篇赏析，不是一份报告。读者应该读到文学，不是读到数据
